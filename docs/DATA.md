## 关系规则

词语的出现位置用 `[start,end)` Unicode 字符偏移记录（Python 字符索引）；当前样例均为 BMP 汉字，浏览器位置一致。扩充含扩展区汉字时必须改用 code point 数组，不直接依赖 JS UTF-16 slice。

lexeme → sense 不是一个词在所有地方都采用某义项。occurrence 必须关联本句位置与本处 sense；导入检查实际字符、词语/义项一致性、外键和重叠。

“之”暂分指代、修饰关系、主谓之间、宾语前置标志。本处用法说明与一般用法分开。某些传统句法名词可能不适合小学生，需教师审核后改写。关于“菊之爱”等争议结构，本轮没有自行纳入确定关系。

## 审核与版本工作流

准备候选 JSON → 事务导入 pending → 校验关系 → 查看来源工作单 → 编辑者核对原句/释义/题目 → 使用本机 review 命令记录审核人和依据 → 逐层发布。

正式可见必须同时满足：教材版本 approved、篇目归属 approved、课内文言文分类、范围真实年级匹配、篇目与句子 approved、义项与出现实例 approved。题目还须自身 approved。撤回任一上游状态后，下游学生视图自动隐藏。

相同导入摘要可重复执行。相同内容 ID 的文本变化会拒绝，不覆盖审核结果；新版内容使用新 ID/版本并重新审核。审核日志保留前后状态、审核人、依据、时间。sample 模式只读独立的临时公开样例数据库，不能打开私有数据库。

内部审核目前是来源工作单 + CLI，有审计链；多角色图形编辑与双人审批尚未实现。

## 数据缺口与解除条件

- 学制确定，但逐册 ISBN/版权版次/印次/使用学年未取得：需要合法来源版权页和目录。
- 当前 3 个片段未绑定教材：需确认年级、册、单元、选段范围、原字形与分类，不能靠常识分配。
- 无人类审核：必须由具备语文教学或编辑能力者核对每种用法、出现实例和题目答案。
- 未取得现代教材注释/译文/配图许可：维持原创解释与原典，不导入这些资源。
- 学习记录样本不足：当前规则是透明启发式，不是诊断模型，未验证教学效果。
- 语音/OCR尚无数据处理约定：上线前补存储、删除、授权和不确定性机制。

候选开源项目 chinese-classical-corpus/chinese-poetry/Jiayan 本轮未采用，也未宣称其许可证、维护状态或教材覆盖已核验。小样例不需要引入通用语料/NLP依赖；扩大抽取时应按 PRD 候选逐仓库审计授权链。
